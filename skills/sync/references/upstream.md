# 되돌려 보내기 — 프로젝트의 배움을 paddock 에 제안하기

sync 6단계(또는 사용자가 「paddock 에 올릴 것 있나」라고 할 때) 한다. **초안만 쓴다** — 이슈·PR 은 사용자가 승인할 때만 만든다.

## 훑을 곳

| 곳 | 후보가 되는 것 |
| --- | --- |
| `.agents/learnings/*.md` | 항목의 `Learning` 이 이 프로젝트의 스택·도메인·경로 없이도 말이 되는 것 |
| `.agents/rules/*.md` (seed) | 같은 실수 사다리로 승격된 규칙 중 프로젝트 고유가 아닌 것 |
| 이번 sync 충돌 | 프로젝트가 고정부를 고친 것 — 고정 문장이 그 프로젝트에서 틀렸거나 모자랐다는 신호 |

## 거르는 기준

- **일반적인가** — 다른 스택·다른 도메인 레포에서도 같은 문장이 맞나. 특정 라이브러리·서비스·경로가 있어야 말이 되면 뺀다
- **이미 있나** — 새 버전 자산(`$STAGE/out`)과 `CHANGELOG.md` 에 같은 뜻이 있으면 뺀다
- **검증됐나** — learnings 는 덜 검증된 배움이다. 근거(`Evidence`)가 한 번뿐이면 「후보 — 근거 약함」으로 표시한다

## 초안 형식

```markdown
## <짧은 제목>

- 대상 자산: `assets/<층>/<경로>` (절 이름) — 고정 문장 수정 / 새 규칙 / 새 슬롯 제안 중 하나
- 제안: <바꿀 문장 또는 더할 문장 — 자산 문체(한국어, 규칙 문장만)>
- 이유: <일반화한 원칙 1~2문장>
- 근거: <어떤 상황에서 드러났나 — 일반화해서>
```

## 공개 안전

paddock 레포는 공개될 수 있다. 초안에서 지운다: 일감 번호·레포 이름·사람 이름·홈 경로·내부 경로·서비스 이름·세션 id·원자료 인용.
지운 뒤에도 뜻이 남는지 본다 — 안 남으면 그 후보는 일반적이지 않은 것이다.

만들기 전에 기계로 한 번 더 본다 — 결과가 0줄이어야 한다:

```sh
. "<대상>/.paddock/config.sh"
grep -nE "$PROJECT_NAME|${ISSUE_PREFIX:-^$}-[0-9]|$HOME|$(basename "$(git -C "<대상>" rev-parse --show-toplevel)")" <초안>
```

## 만들기 (승인 뒤)

paddock 레포 = 플러그인 `.claude-plugin/plugin.json` 의 `repository`.

- 이슈: `gh issue create -R <owner>/<repo> --title … --body-file <초안>` — 기본
- PR 은 사용자가 paddock 클론을 갖고 있고 원할 때만. 자산을 고치면 그 레포의 `AGENTS.md` 「자산 수정」·검증 명령을 따른다
