# 출고 옵션 — 제안할 때 떠올릴 유형

**예시이지 정답이 아니다.** paddock 은 출고 방식을 정하지 않는다. 이 목록은 한두 방식으로 쏠리지 않게 넓게 보려는 것이고,
도구·명령·설정은 적용할 때 그 프로젝트에 맞춰 찾는다(웹 검색으로 지금 문서를 본다). 목록에 없는 방식도 된다.

| 유형 | 떠올릴 만한 경우 | 확인할 것 |
| --- | --- | --- |
| 머지 즉시 배포 | 웹 서비스·내부 도구, 기본 브랜치 = 운영 | 머지로 도는 CI·배포, 되돌리는 법 |
| 태그로 출고 | 버전이 있는 라이브러리·CLI, 수동으로 끊는 출고 | 버전 파일, 태그를 누가 언제 다는지, 릴리즈 노트 |
| 자동 버전 PR | 커밋·변경 노트로 버전을 계산하는 패키지 | 커밋 메시지·변경 노트 관례, 레지스트리 게시 권한 |
| PR 을 모아 출고 | 여러 PR 을 함께 시험하고 한 번에 내보내는 앱 | 모으는 브랜치의 수명, 모은 뒤 수정 방법 |
| 스토어 심사 | 모바일·데스크톱 앱 스토어 | 빌드 서명, 심사 대기, 단계적 배포 |
| 수동 | 출고가 드물거나 아직 사용자가 없음 | 무엇을 기록으로 남길지 |
| 정하지 않음 | 지금은 필요 없음 | — |

여러 유형을 섞어도 된다(예: 서비스는 머지 즉시, 클라이언트 앱은 스토어).
