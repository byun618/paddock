# 에이전트 도구 — 가용성 확인과 첫 사용 화면

역할을 맡는 **에이전트 도구**(Codex·Grok·Claude …)마다 「쓸 수 있나」를 확인하는 명령과, 처음 쓸 때 사람이 치워야 하는 화면이다.
harness(세션을 띄우고 화면을 읽는 도구) 와 무관하다 — 화면을 읽어야 하는 확인은 능력 이름(『세션 기동』·『화면 관측』·『회수·정리』)으로 적었고,
그 명령은 선택한 harness 매핑에 있다.

- **규칙은 여기 없다.** 언제 확인하고 결과로 무엇을 하는지(카탈로그 먼저·90%·확인 실패·기동 확인·전환·기록)는
  [`defaults.rules.md`](defaults.rules.md) 「리뷰어 사용 불가 시 자동 전환」·「외부 서치 한도 소진 시 생략」이 원본이다. 이 파일은 **방법**만 둔다
- **이 파일에 절이 없는 도구는** 카탈로그·사용량 모두 「확인 실패」로 다룬다(규칙대로 기동 확인으로만 잡는다).
  프로젝트가 새 도구를 쓰기 시작해 확인 방법을 찾았으면 paddock 에 되돌려 보낸다
- 명령은 아래 적은 도구 버전에서 확인했다. 도구가 바뀌어 출력 형식이 다르면 「확인 실패」다 — 짐작해서 다른 명령을 치지 않는다
- 명령 블록은 `set -e`·`pipefail` 셸에서도 끝까지 돌아 세 값(있음/없음/확인 실패) 중 하나를 찍게 썼다 — 고칠 때도 그렇게 둔다

## Codex

확인한 버전: codex-cli 0.162.1 (사용량 로그 형식은 0.159.2 에서 처음 확인). 필요: `jq`. 홈은 `CODEX_HOME` 이 있으면 그쪽이다.

### 카탈로그 확인

`codex debug models` 는 서버에서 갱신한 **계정 카탈로그**를 낸다. `--bundled` 는 바이너리 내장 목록이라
계정이 못 쓰는 모델도 들어 있다 — 부재 판정에 쓰지 않는다.

```bash
id='<defaults.md 의 식별자>'
if ! command -v codex >/dev/null 2>&1 || ! command -v jq >/dev/null 2>&1; then echo '확인 실패 (codex 또는 jq 없음)'
else
  slugs=$(codex debug models -c check_for_update_on_startup=false 2>/dev/null | jq -r '.models[].slug' 2>/dev/null | sort) || slugs=''
  bundled=$(codex debug models --bundled -c check_for_update_on_startup=false 2>/dev/null | jq -r '.models[].slug' 2>/dev/null | sort) || bundled=''
  if [ -z "$slugs" ]; then echo '확인 실패 (출력 없음)'                     # ① 출력이 비었는지 먼저
  elif [ "$slugs" = "$bundled" ]; then echo '확인 실패 (내장 목록과 같음)'    # ② 갱신 실패로 내장 목록에 떨어졌을 수 있다
  elif printf '%s\n' "$slugs" | grep -qxF "$id"; then echo '있음'            # ③ 정확히 같은 줄
  else echo '없음'; fi
  printf '%s\n' "$slugs"                                                    # 판정에 쓴 목록 원문
fi
```

- ③ slug 한 줄씩을 지정 식별자와 **정확히 같은 줄**로 대조한다. `visibility: hide` 여도 목록에 있으면 「있음」이다
- **갱신 실패 시 내장 목록으로 조용히 떨어질 수 있다** — 서버 갱신에 실패하면 이 명령이 exit 0·stderr 없이 `--bundled` 와 같은 목록을 내서
  계정에 없는 모델이 「있음」으로 나올 수 있다(무인증·캐시 없음에서 재현. 캐시가 신선하면 오프라인이어도 계정 목록이 나왔다 — 캐시 상태에 따라 다르다).
  ② 는 그 경우를 「확인 실패」로 돌린다 — 계정 목록이 실제로 내장 목록과 같은 계정도 「확인 실패」가 되지만, 그 쪽이 안전하다.
  그래도 「있음」은 띄워도 된다는 보장이 아니다 — 거절은 규칙의 기동 확인에서 잡는다
- `-c check_for_update_on_startup=false` 는 이 명령 실행에만 업데이트 확인 설정을 끈다
- 이 명령은 `CODEX_HOME` 아래 모델 캐시를 갱신할 수 있다 — 설정 파일이 아니라 도구 캐시다

### 사용량 확인

`rate_limits` 가 든 **가장 최근** Codex 세션 로그의 마지막 `rate_limits` 를 읽는다. 최신 파일 하나만 보면 안 된다 —
거절된 세션·빈 세션은 `rate_limits` 를 남기지 않아서 그것이 최신이면 빈 출력이 된다.

```bash
cx="${CODEX_HOME:-$HOME/.codex}"; f=''; n=0
for x in $(find "$cx/sessions" -name 'rollout-*.jsonl' 2>/dev/null | sort -r); do   # 경로 = 날짜 샤드 + 시작 시각 → 최근 것부터
  n=$((n+1)); [ "$n" -gt 50 ] && break                                               # 최근 50개까지
  if grep -q '"rate_limits":{.*"plan_type"' "$x"; then f=$x; break; fi
done
if [ -z "$f" ]; then echo '확인 실패'
else echo "$f"; grep -o '"rate_limits":{.*"plan_type"[^}]*}' "$f" | tail -1 || true; fi
```

- 최근 50개 안에 없으면 「확인 실패」다. 읽은 파일 경로도 같이 적는다
- 순서는 파일 경로(세션 **시작** 시각)다 — 오래된 세션을 이어 쓴 기록은 뒤로 밀린다
- `plan_type`(등급)과 창마다 `used_percent`(사용률)·`window_minutes`(창 길이)·`resets_at`(초기화, epoch 초)를 읽는다 —
  `secondary` 가 `null` 이 아니면(창이 둘인 등급, 예: 5시간 + 주간) 두 창 모두다. 확인 시각은 `date +%s` 로 같이 찍는다
- 창 길이는 등급마다 다르다(주간 10080분, 무료 등급에서 30일 43200분을 본 적이 있다). 값은 **마지막 Codex 호출 시점**의 서버 응답이라
  그 뒤 다른 기기 사용분은 빠져 있다
- 리뷰 한 세션이 주간 창의 1~3% 를 쓴 실측이 있다. 다른 창 길이에서의 세션당 사용률은 실측이 없다

### 기동 확인에서 보이는 것

- 거절(`model_not_found` 400 등)은 첫 턴 제출 뒤 수 초 안에 화면에 원문으로 뜨고 Codex 는 입력 대기로 돌아갔다 —
  preamble 없이 직접 주입한 경로에서 +3초에 본 것이다. 감독 경로에서 보고가 오는지는 실측하지 못했다. 한도 초과도 같을 것으로 보이나 관측은 400 뿐이다
- 업데이트 안내 아래 입력 대기로 멈추는 일이 카탈로그에 있는 모델에서도 일어났다 — 모델 부재의 신호가 아니다. 원인은 가르지 못했다

### 첫 사용 화면

- **업데이트 메뉴** — 새 버전이 있으면 기동 때 선택 메뉴가 뜨고 입력을 막는다. harness 의 준비 판정이 이 메뉴를 「준비」로 볼 수 있다.
  harness 가 기동 인자를 넘기지 못할 수 있어 **사용자 설정 `config.toml`(`CODEX_HOME` 아래) 에 `check_for_update_on_startup = false`** 를 권한다 —
  사용자 전역 설정이라 adopt·코디는 쓰지 않고 제안만 한다. 설정이 없으면 Codex pane 은 첫 주입 전에 화면을 읽는다(매핑 『준비 대기』)
- **trust** — 처음 여는 디렉터리에서 신뢰 여부를 물을 수 있다. 사람이 치운다

## Grok

확인한 버전: grok 1.0.70.

### 카탈로그 확인

계정 카탈로그를 내는 명령을 확인하지 못했다 — 「확인 실패」.

### 사용량 확인 (주간 한도)

- 『세션 기동』으로 Grok 세션을 띄워 기동 배너의 `Weekly limit left: N%` 를 『화면 관측』으로 읽고, **입력 없이** 『회수·정리』로 닫는다.
  `N` 은 **남은** 비율이다(사용률이 아니다)
- 선택한 매핑에서 『세션 기동』·『화면 관측』이 공백이면(Grok 을 띄우거나 화면을 읽을 수 없으면) 「확인 실패」다
- 인증 상태 조회(`grok_status` 등)는 인증만 보여 주고 한도를 주지 않는다 — 한도 확인에 쓰지 않는다
- **그 줄이 늘 있는 것은 아니다** — 같은 버전에서 한도가 소진됐을 때 `Weekly limit left: 0%` 가 떴고, 여유가 있던 다른 날 배너에는 그 줄이 없었다(관측 두 번).
  줄이 없거나 형식이 다르면 「확인 실패」다 — 소진으로 보지 않는다
- 처음 여는 디렉터리면 trust 화면이 배너보다 먼저 뜬다 — 사람이 치운 뒤에야 배너를 읽을 수 있다(아래 「첫 사용 화면」)

### 첫 사용 화면

- **trust** — 처음 여는 디렉터리(새 레포·새 worktree)에서 신뢰 여부를 묻고 입력을 막는다. 사람이 치운다

## Claude (Claude Code)

### 카탈로그 확인 · 사용량 확인

계정 카탈로그·사용량을 조회하는 명령이 없다 — 둘 다 「확인 실패」. 접근할 수 없는 모델·한도 초과는 규칙의 기동 확인(첫 턴 뒤 화면의 오류)으로만 잡는다.

### 첫 사용 화면

- **trust** — 처음 여는 디렉터리에서 신뢰 여부를 물을 수 있다. 사람이 치운다

## 언제 이 파일을 쓰나

| 때 | 누가 | 무엇을 |
| --- | --- | --- |
| adopt 설계 | adopt | `defaults.md` 의 지정 리뷰어 후보를 카탈로그 확인으로 대조 — 「없음」이면 지정 리뷰어로 제안하지 않는다. 「있음」은 미보증이라 보고에 그렇게 적는다 |
| adopt 검증 | adopt | 세션을 띄우지 않는 확인만(명령 블록) 도구마다 한 번 돌려 보고 — 화면을 읽어야 하는 확인(Grok 한도)은 첫 사용 화면을 치운 뒤 작업 시작 때. 첫 사용 화면을 미리 치우라고 사람이 할 일에 적는다 |
| 작업 시작 | 본체(task-start) | 기동 전 확인 — 결과를 `00-start.md` 에 한 줄 |
| 리뷰 라운드마다 | 코디 | `defaults.rules.md` 「리뷰어 사용 불가 시 자동 전환」 |
| 외부 서치 전 | 코디 | `defaults.rules.md` 「외부 서치 한도 소진 시 생략」 |
