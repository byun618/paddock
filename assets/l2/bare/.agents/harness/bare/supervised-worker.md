## 『감독 워커 기동』

### 명령
```bash
# 없다. 『세션 기동』 + 『준비 대기』 + 『본문 주입』을 사람이 순서대로 하고 사람이 기록한다.
```

### 보장 수준
**공백.** 일감(Task)과 시도(Dispatch)를 묶는 기록이 없다. 무엇을 누구에게 언제 맡겼는지는 **사람이 작업 폴더
(`{{SPECS_ROOT}}/…`)에 적어야만** 남는다 — 그것이 이 도구의 유일한 원장이다.

### 상황 → 행동
- **차단 화면**: 『준비 대기』와 같다.
- **타임아웃·빈 결과**: 해당 없음 — 이 능력에 기다릴 호출이 없다(사람이 세 능력을 순서대로 한다).
- **부분 실패**: 세 단계 중 어디까지 갔는지 도구가 기억하지 않는다 — 사람이 단계마다 작업 폴더에 적는다.
- **복구**: 기록이 없으면 처음부터 다시 한다. 중복 지시가 들어갔을 가능성을 판정표에 적는다.
- **하지 말 우회**: "띄웠으니 맡겨졌다" 로 적지 않는다. 이 도구에서 워커 기동은 **사람의 기록**이다.

### 재사용 인자 규칙 (절차 문서가 가리키는 그 규칙)

**규칙이랄 것이 없다 — 그것이 이 도구의 위험이다.** tmux·iTerm2 는 "새 기동" 과 "pane 재사용" 을
구분하는 인자를 갖지 않는다. 둘 다 그냥 대상 pane 에 텍스트를 보내는 같은 명령이고, 모델·effort·advisor·
worktree 를 나중에 바꿀 수단도 없다(기동 시 명령줄에 박은 것이 끝이다).
따라서 **어느 pane 이 어떤 구성으로 떠 있는지는 사람이 남긴 기록에만 있다** — 도구에 물어볼 수 없다.
재사용하려면 그 기록을 먼저 확인하고, 없으면 재사용하지 않고 새로 띄운다.
