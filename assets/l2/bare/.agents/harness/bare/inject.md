## 『본문 주입』

### 명령
```bash
tmux load-buffer -b <버퍼명> <본문 파일>
tmux paste-buffer -b <버퍼명> -t <대상>          # 붙여 넣기 (큰 본문)
tmux send-keys -t <대상> Enter                # 제출은 따로
# iTerm2 — 사람이 붙여 넣는다 (Python API: Session.async_send_text)
```

### 보장 수준
**공백.** 보낸 쪽에 ack 가 없다. iTerm2 `async_send_text` 는 "사용자가 타이핑한 것처럼" 넣고 아무것도 돌려주지
않는다. tmux 도 대상 프로그램이 그 바이트를 읽었는지 알려주지 않는다. **"정확히 한 번" 을 보장하는 장치가
없으므로 사람이 센다.** 판정표의 배달 칸은 `공백` 이다.

### 상황 → 행동
- **차단 화면**: 위 『준비 대기』의 사고 그대로 — 보내기 전에 반드시 화면을 읽는다.
- **타임아웃·빈 결과**: 기다릴 대상이 없다.
- **부분 실패**: 두 번 보내면 두 번 들어간다. 보낸 시각·본문·`(pane_id, pane_pid)` 를 원자료로 남기고,
  재전송 전에 화면을 읽어 이미 들어갔는지 사람이 확인한다.
- **복구**: 불확실하면 **다시 보내지 않고** 화면과 『세션 기록 오라클』을 본다.
- **하지 말 우회**: `send-keys` 로 본문과 Enter 를 한 번에 넣으면 붙여넣기 감지가 있는 provider 에서 통째로
  거절될 수 있다 — 본문과 제출을 나눈다. 그리고 **그 성공을 배달 증명으로 쓰지 않는다.**
