## 『본문 주입』

### 명령
```bash
orca terminal send --terminal <handle> --text "<본문>" --enter --wait-submit <초> --json   # 수락과 제출 관측을 나눠 돌려준다
orca terminal send --terminal <handle> --text "<본문>" --enter --retry-request <id> --json   # 전달 불명일 때 같은 명령을 그 id 로
orca worktree create --name <name> --agent <id> --prompt "<본문>" --json    # 생성과 함께 첫 지시
```

### 보장 수준
**관측 — 정확히 1회는 증명되지 않는다.** 이 도구에는 `terminal prompt` 에 해당하는 명령이 없다. 계약에 따르면 text + Enter 입력의 응답은
입력 수락과 제출 관측·턴 시작을 나눠 돌려주고, `--wait-submit` 은 정해진 시간만 지켜보며 시간이 지나도 다시 보내지 않는다.
`--retry-request` id 는 본문과 터미널 프로세스에 묶여 같은 요청의 중복 실행을 막는다. 다만 세션 기록에 1건 들어갔다는 값은 돌려주지 않는다.
판정표 근거에는 받은 값과 「관측」을 적고, 사후 확인은 『세션 기록 오라클』로 한다. 오래된 호스트는 raw 입력만 받고 제출 관측·재시도를 주지 않는다.

### 상황 → 행동
- **차단 화면**: 차단 화면에 `orca terminal send` 를 하면 그 화면에 대한 대답으로 먹힌다 — 본문이 사라지고 흔적도 남지 않는다.
  그래서 **보내기 전에 반드시 화면을 읽는다.**
- **타임아웃·빈 결과**: `--wait-submit` 시간 초과는 수락까지만 됐다는 뜻이고 다시 보낸 것이 아니다. 실패로 읽어 재전송하지 않는다.
- **부분 실패**: `--retry-request` 없이 두 번 보내면 두 번 들어간다. 보낸 시각과 본문을 원자료로 남기고,
  재전송 전에 『화면 관측』으로 이미 들어갔는지 확인한다. **`--terminal` 값이 비면 호출한 쪽 터미널로 간다** — 본문이 자기 입력창에 들어가고도 `accepted: true` 가 나온 적이 있다(1.4.198 관측). 빈 handle 이면 보내기 전에 중단하고, 응답의 `handle` 이 의도한 값인지 대조한다.
- **복구**: 들어갔는지 불확실하면 **새 요청으로 다시 보내지 않고**, 보고된 `--retry-request` id 로 똑같은 명령을 내거나 화면과 세션 기록을 본다. 중복 주입이 의심되면
  그 사실을 판정표 근거 칸에 적는다.
- **하지 말 우회**: exit 0 이나 `accepted: true` 를 배달 증거로 쓰지 않는다. 판정표의 배달 칸에
  "보냈다" 를 적지 않는다.
