## 『게이트 알림』

### 명령
```bash
# 보내는 쪽 — 코디 터미널의 셸에서, 멈추기 직전에 한 번
afplay /System/Library/Sounds/Glass.aiff
# 대체 경로 — 본체 세션에서. 본체는 기록된 코디 handle 을 쓴다
orca terminal wait --terminal <handle> --for tui-idle --timeout-ms 120000 --json
orca terminal read --terminal <handle> --screen --json
```

### 보장 수준
**재생 요청은 관측, 들었는지는 공백이다.** `afplay` 의 exit 0 은 재생을 마쳤다는 뜻이고, 음소거거나 자리를 비웠으면 아무도 못 듣는다.
레지스트리에 알림 명령이 없어 macOS 를 직접 부른다. 소리가 없는 환경은 **공백**이고 판정표가 아니라 게이트 보고에 적는다.
OS 알림(`osascript`)은 쓰지 않는다 — 권한이 없으면 exit 0 인 채 아무것도 뜨지 않아 실패가 가려진다.
대체 경로의 `tui-idle` 은 **조용하다는 관측**이지 게이트라는 뜻이 아니다 — 화면을 읽어 무엇을 묻는지 확인해야 한다.
알림은 승인 경로도 판정 근거도 아니다. 승인은 코디 터미널에서 받는다.

### 상황 → 행동
- **차단 화면**: 코디가 차단 화면에 막히면 코디는 알림을 보낼 수 없다. `tui-idle` 은 차단 화면과 준비를 가리지 못하므로 대체 경로에서 화면을 읽어 가른다.
- **타임아웃·빈 결과**: `orca terminal wait` 의 타임아웃은 코디가 아직 출력 중일 수 있다는 뜻이다. 다시 기다린다.
- **부분 실패**: `afplay` 가 0 이 아니면(없음·샌드박스 거절) 게이트 보고 끝에 그 사실을 한 줄 적고 그대로 멈춘다. **알림 실패로 게이트 흐름을 바꾸지 않는다.**
- **복구**: 소리가 안 들린다고 사용자가 말하면 음량·출력 장치를 안내하거나, 본체 세션이 대체 경로로 코디를 지켜본다.
- **하지 말 우회**: 소리가 났다는 것을 승인이나 판정의 근거로 쓰지 않는다.
