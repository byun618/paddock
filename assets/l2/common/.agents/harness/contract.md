# 하네스 능력 계약 — 계약 정의

능력 이름·보장 어휘·능력 목록은 [capabilities.md](capabilities.md). 이 파일은 매핑을 쓰거나 고치는 사람·리뷰어가 보는 계약과,
절차 문서·매핑이 `contract.md H<n>` 으로 가리키는 도구 무관 사실이다.

## 네 가지 증명 대상 (매핑마다 이 네 줄의 칸이 있다)

배달 정확히 1회 · pane 세대 불변 · 오래된 시도 보고 배제 · 사람 개입. 각 매핑의 「보장 요약」 표가 이 네 줄을
증명/관측/공백으로 채운다. 채우지 않은 매핑은 쓸 수 없다.

## 매핑은 요구 명령을 스스로 선언한다 (『전제 점검』이 대조할 대상)

각 매핑은 **자기가 요구하는 명령 집합을 한 블록에 명시한다** — 본문을 훑어 짐작하는 것이 아니라 선언이다.
선언은 매핑 폴더의 `commands.md` 한 곳에 둔다 — 능력 파일은 명령을 쓰고, 이 파일은 그 명령을 선언한다.
코디네이터 쪽 명령만이 아니라 **워커가 보고에 쓰는 명령까지** 넣는다. 그것이 빠지면 워커가 못 돌아오는데도
『전제 점검』은 조용히 통과한다. 선언이 없거나 비어 있으면 **요구 0개 = 통과** 가 되므로, 대조 도구는
그 경우를 통과가 아니라 **불일치로 멈추도록** 만든다.

선언은 두 칸이다 — `required-commands`(이 매핑이 **실행을 지시하는** 명령)와 `mentioned-commands`(이름만
나오고 호출하지 않는 것: 없는 명령·폐기된 별칭·"쓰지 말라"). **mentioned 에는 사유 주석이 필수**고,
**mentioned 의 이름으로 실행을 지시하면 오류**다. 그래야 "없다고 적어 둔 명령" 칸이 조용한 통과 경로가 되지 않는다.

## 표기 허용 목록 — 아는 표기만 허용하고 나머지는 오류다

**매핑 파일(공통부·능력 파일)의 명령 표기는 허용 목록에 있는 형태만 쓴다.** 목록은 `capability-check.mjs` 머리 주석의
A1~A8 이고, 거기 없는 형태는 통과가 아니라 **오류**다. 매핑이 어떤 표기를 꼭 써야 하면 목록에 올린다 —
**올리면 그 형태도 검사를 받는다.** 요약하면:

| 허용 | 형태 | 비고 |
| --- | --- | --- |
| A1·A2 | `<도구> [전역옵션…] <그룹> <명령> [플래그…]` · `<도구> [전역옵션…] <명령> [플래그…]` | 전역옵션도 **목록**이다. 목록 밖 옵션이 명령 앞에 오면 오류 |
| A3 | `node <경로>/<도구>.mjs …` | 매핑이 권하는 대체 호출형 — **도구 표기로 정규화해 검사한다** |
| A4 | `tmux [전역옵션…] <명령> …` | `-L`·`-S`·`-f` 가 전역옵션 |
| A5 | `async_<이름>(…)` | iTerm2 Python API |
| A6 | 플래그 없는 **이름 언급** | 접두사 생략 가능. 단 레지스트리에서 **유일 해소** |
| A7 | 허용된 외부 명령 | 목록에 올린 것만(`node`·`jq`·`git`·에이전트 CLI 등) |
| A8 | `<오류코드>: <메시지>` 인용 | 명령 표기가 아니다 |

왜 이렇게 좁히나: **"산문에서 명령을 더 똑똑하게 뽑는" 방식은 새 사각을 계속 냈다.** 허용 목록은 반대
방향이다 — 모르는 표기가 통과 쪽으로 떨어지지 않는다. **검사기는 한 벌이다**: 표기를 검사하는 다른 도구가
생겨도 자기 판을 두지 않고 이 스크립트의 분류기를 그대로 가져다 쓴다. 목록이 두 벌이면 한쪽만 좁아진다.

대조 방향은 넷이다 — ① 선언이 비지 않았나 ② 표기가 허용 목록에 있나 ③ 본문이 쓰는 명령 ⊆ 선언
④ `required` ⊆ 런타임 광고. **광고가 없는 도구(bare)에서는 ①②③ 이 돌고 ④ 만 공백이다**
(bare 의 어휘는 그 매핑의 선언 자신이다).

**검사기는 자기가 못 보는 것을 스스로 적는다.** `capability-check.mjs` 머리 주석에 「알려진 한계」 절이 있다. 그중 하나는
매핑을 쓰는 사람이 반드시 알아야 한다 — **검사 대상은 코드 스팬과 펜스 블록 줄뿐이다.** 백틱 없는 산문에
도구 이름 없이 `<서브명령> --<플래그> <값>` 처럼 쓰면 어느 방향에도 걸리지 않는다. 그래서 **명령은 반드시 코드 스팬으로 쓴다.**

**네 방향이 보지 않는 것 — 역방향.** 넷 다 "매핑이 쓰는 것" 을 검사한다. 매핑이 **광고에 있는 능력을
"없다·못 한다" 고 적으면 어느 방향에도 걸리지 않는다** — 언급만 칸은 사유를 요구하지만 사유의 사실 여부는
보지 않는다. **"없다" 를 적을 때는 광고 목록을 그 자리에서 대조한다** — 관문은 이 문장을 지켜 주지 않는다.

## 도구 무관 사실

- **H1 — codex 의 `$HOME/.codex/history.jsonl` 은 완료 오라클이 아니다.** TUI 의 **입력 재호출 로그**이고
  한 줄은 사용자가 친 한 턴(`{session_id, ts, text}`)이다. `persistence = "none"` 이면 조용히 안 쓰므로
  줄이 없을 때 "배달 실패" 와 "기록 생략" 을 가를 수 없다. 따라서 **입력 관측이며 증명이 아니다.**
  완료는 『완료 감지』로, 배달은 『본문 주입』으로 본다.
- **H2 — 사람 개입 흔적은 『화면 관측』으로만 회수된다.** 구조화된 워커 조회는 사람이 GUI 에 직접 넣은 입력을
  보지 못한다. 어느 도구에서도 이것은 관측이고 증명이 될 수 없다.
- **H5 — 빌린 pane 과 소유한 pane 의 회수가 다르다.** 내가 띄운 pane 은 정리하면 닫히고, 사람이 띄워 준 pane
  (또는 재사용으로 소유권이 넘어간 pane)은 **남아서 따로 닫아야 한다.** 남은 pane 을 정리했다고 보고하지 않는다.
- **H6 — 세션 기록 위치와 읽는 법.** 아래는 **기본값**이고, 각 provider 는 홈을 옮기는 환경변수를 가진다 —
  **경로를 짐작하지 말고 도구가 돌려주는 값을 쓴다**(주입 응답이 기록 경로를 돌려주는 도구는 그 값을 쓴다).

  | provider | 기본 경로 | 홈을 옮기는 환경변수 |
  | --- | --- | --- |
  | Claude | `$HOME/.claude/projects/<인코딩된 cwd>/<session-id>.jsonl` | `CLAUDE_CONFIG_DIR` (홈). **`CLAUDE_CODE_PROJECT_DIR_NAME` 은 독립 축이 아니다** — `CLAUDE_CONFIG_DIR` 와 **함께일 때만** 폴더 이름을 바꾼다(아래 조건) |
  | Codex | `$HOME/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` (**날짜 샤드**) · 입력 재호출은 `$HOME/.codex/history.jsonl` | `CODEX_HOME` |
  | Grok | `$HOME/.grok/sessions/<URL 인코딩된 cwd>/<id>/` — **디렉터리다.** 아래 표 참조 | `GROK_HOME` |

  환경변수가 설정돼 있으면 `$HOME/...` 경로는 **틀린다**. 인코딩 규칙도 짐작하지 않는다 —
  비영숫자를 `-` 로 바꾸고 200자를 넘으면 자른 뒤 전체 경로 해시를 붙인다.

  **Claude 의 폴더 이름을 바꾸는 변수는 조건이 붙는다 — 독립 축이 아니다.**
  공식 세션 문서(`https://code.claude.com/docs/en/sessions` 「Name the project directory yourself」)대로:
  - **`CLAUDE_CONFIG_DIR` 와 함께 두어야 한다.** `CLAUDE_CONFIG_DIR` 이 없으면 `CLAUDE_CODE_PROJECT_DIR_NAME` 은
    **무시된다** — 그때 기록은 파생 이름(인코딩된 cwd) 그대로다.
  - **값은 1–64자의 영숫자·하이픈·밑줄만.** 그 밖의 값은 **무시하고 파생 이름**을 쓴다.
  - **`claude` 를 띄우는 셸 환경에서만** 먹는다 — 설정 파일의 `env` 블록으로는 설정되지 않는다.
  - Claude Code **v2.1.234 이상**.

  그 조건이 모두 맞을 때 기록은 `$CLAUDE_CONFIG_DIR/projects/<그 이름>/<session-id>.jsonl` 이다. 같은
  `CLAUDE_CONFIG_DIR` 로 띄우면서 이 변수만 빼면 **다시 파생 이름 디렉터리를 읽고 쓴다.**
  즉 **이름 변수만 켰다고 cwd 로 계산한 경로가 틀리는 것이 아니다** — 무시되는 세 경우(홈 변수 미설정 ·
  값 형식 위반 · settings `env` 설정)에는 파생 경로가 맞다. 그래도 **경로는 짐작하지 말고 도구가 돌려주는
  값을 쓴다**(위 첫 줄).

  **Grok 은 한 세션이 디렉터리 하나다. 어느 파일을 여는지가 판정을 바꾼다:**

  | 파일 | 첫 줄 키 | 무엇 |
  | --- | --- | --- |
  | `updates.jsonl` | `timestamp`·`method`·`params` | **배달 판정에 쓰는 파일** — 기록 경로를 돌려주는 도구는 이 파일을 가리킨다 |
  | `chat_history.jsonl` | `type`·`content` | 대화 모양의 기록 — 사람이 읽기엔 이쪽이 가깝다 |
  | `events.jsonl` | `ts`·`type`·`servers` | MCP·도구 이벤트 |
  | `prompt_context.json`·`summary.json`·`system_prompt.txt` | (JSON/텍스트 한 덩이) | 스냅샷류 |

  공식 문서는 **파일 이름을 정하지 않는다**(작업 디렉터리 키로 저장한다는 것까지). 그래서 이 표는
  **한 환경에서의 실측**이고, 경로 칸을 증명으로 올리지 않는다 — 여는 파일이 다르면 빈 결과가 나온다.
  **한 줄을 열어 키를 확인한 뒤** 세는 것이 규칙이다.
  세 기록 모두 **사람이 친 입력과 주입된 입력을 가르는 필드가 없다** — 그래서 H2 가 남는다.
  codex `history.jsonl` 은 `max_bytes` 가 걸리면 오래된 줄을 버리기도 한다 — 줄이 없다는 것이 더더욱 증거가 아니다.

  **읽는 방법 (모든 매핑의 『세션 기록 오라클』이 이 블록을 가리킨다).** 경로를 인자로 준다.
  아래는 Claude 형식(JSONL, 줄마다 `type`)이다 — Codex·Grok 기록도 JSONL 이지만 필드 이름이 달라
  **먼저 한 줄을 열어 키를 확인한 뒤** 같은 요령으로 읽는다.

  ```bash
  # 무엇이 들어갔고(user) 무엇이 응답됐나(assistant)
  jq -r 'select(.type=="user" or .type=="assistant")
         | [.type, (.message.role // "-"),
            ((.message.content | if type=="array"
               then (map(.text // ("["+(.type//"?")+"]")) | join(" "))
               else (. // "") end) | tostring | gsub("\\s+";" ") | .[0:80])]
         | @tsv' <세션 기록 .jsonl 절대경로>
  # 줄 종류만 세고 싶으면
  jq -r '.type' <세션 기록 .jsonl 절대경로> | sort | uniq -c | sort -rn
  ```

  기록의 user 줄은 사람이 친 입력과 주입된 입력이 **같은 모양**이다 — 그래서 이 읽기는 관측이다.
- **H4 — 워커가 일감 본문을 읽었는지를 판정 가능하게 한다.** 워커 preamble 은 제어 도구의 제품 코드이고
  이 절차는 그것을 고치지 않는다. 대신 두 가지로 막는다: ⓐ 코디네이터가 착수 시 일감 본문을
  `{{SPECS_ROOT}}/{{TASK_NAME}}/00-analysis.md` 에 스냅샷한다 (작업 산출물이 진실의 원천이므로 워커가 일감 조회 도구를 못 써도
  내용이 빠지지 않는다) ⓑ 일감 명세의 첫 단계를 "일감 조회 결과를 원자료로 남기거나, 못 읽으면 그 사실과
  오류 원문을 원자료로 남긴다" 로 둔다. 읽었는지가 파일로 판정된다. 이 방식은 모든 매핑에 똑같이 적용된다.
  **일감이 없는 과제(스모크·검증 순환·사람이 말로 준 짧은 일)는 조회할 대상이 없다** — 그때는 ⓑ 를 생략하고
  **생략했다는 사실과 지시 본문의 출처(누가 어디서 준 전문인지)를 명세 첫 줄에 적는다.** 없는 조회를
  한 척하지 않고, 조회 단계가 빠진 이유가 명세에 남는다.
- **H8ⓐ — 예산 원장은 항상 명시한다.** 관문 스크립트가 예산 원장을 환경변수로 받는다면(원장이 있는
  프로젝트), 그 변수를 비우면 기본 경로로 조용히 풀리고, 구현 브랜치 체크아웃의 원장은 작업 브랜치 원장보다
  항상 뒤처져 **이미 쓴 예산을 다시 내주는** 경로가 열린다. 오타는 fail-closed 지만 **생략은 조용히
  통과한다** — 절차가 막아야 한다. 판정표의 **원장 칸**이 그 장치다. 원장이 없는 프로젝트는 그 칸에
  `해당 없음 — 원장 없음` 을 적는다(빈칸 금지).
- **H8ⓑ — 플래키 검사는 재실행 횟수를 판정표에 적는다.** 통과한 회차만 적고 넘기면 "재실행하면 통과" 가
  습관이 되고 그건 관문이 아니다. 판정표의 **실행 n/총 m 칸**이 그 장치다.
